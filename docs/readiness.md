# RustDesk 稳定后才执行的工作

本分支仅准备嵌入式管理合同。当前未连接真实 RustDesk，不提供可部署的宿主插件或安装包。

接入前记录 RustDesk 精确 revision、Rust/Flutter 工具链和固定依赖；先完成 Windows 主机/观看端构建与正常串流、音频、输入、重连验证，再评估 Wayland/macOS。

之后按顺序完成：

1. 统一 Rust 工具链与锁定依赖，明确哪些原生构建携带管理库。
2. 在 RustDesk 主机生命周期内接入身份存储、配对界面、NativeHost、NativeJournal、启动与 shutdown hook。
3. 验证 service/桌面用户切换、凭据撤销、睡眠恢复、存储失败、断线执行与丢失收存回执。
4. 用真实主机验证 实际运行版本和 ready 证据；替身测试只代表协议与恢复机制。
5. 实现原生对端安装身份认证、授权列表接入和会话撤销：新会话需有效租约，规则移除、断线及租约过期后关闭不再授权的会话。硬件和编码等设置始终由 RustDesk 主控端选择，不增加服务端配置写入。
6. 测量串流性能后再决定媒体链路改造。

不接管旧版本服务或旧状态目录，也不自动迁移旧任务和凭据。
