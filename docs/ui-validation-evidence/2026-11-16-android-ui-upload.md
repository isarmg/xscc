# 2026-11-16 小米 13 UI 提交瓶颈

## 已测：Android 4.0.0-beta.8 与 beta.9

手机为小米 13 / Adreno 740。Windows 被控端保持 4.0.0-beta.8、已验收驱动及物理 60Hz 主屏；复用已有 1920×1080、120Hz 虚拟屏，不创建、撤销或切换主屏。调试通过 USB，媒体为 TCP+UDP。未操作浏览器或桌面全屏。

每个无剖析对照运行原生窗口测试源 45 秒，随后自动退出；下表取开始后第 10–40 秒的逐窗口统计中位数。原生提交节奏分别为 119.999 和 120.001Hz，不把原生提交次数当成手机显示帧数。

| 包 | 接收 FPS | 解码 FPS | UI 接受帧 FPS | UI 回调平均耗时 ms | 各窗口排队 p95 的中位数 ms |
| --- | ---: | ---: | ---: | ---: | ---: |
| beta.8 / `ba20d5dd429b` | 99 | 99.5 | 80.5 | 6.260 | 13.867 |
| beta.9 / `0ea1ec7695c9` | 117 | 116.5 | 85.5 | 5.145 | 9.492 |
| beta.10 / `a92cfe75a920` | 108.5 | 109 | 94 | 9.290 | 16.872 |

beta.9 UI 提交范围为 64–93 FPS，尚未稳定跟上接收/解码。这里的 UI 计数表示界面接受帧，不保证 GPU 完成或面板扫描完成。不得把此轮结果写成“稳定 120 FPS”或“UFO 60Hz 已解决”。手机面板与应用 Surface 的请求和实际显示模式仍为 120Hz。

两轮独立的 15 秒 simpleperf 剖析均无丢样本。beta.8 主线程共 1,503 样本，atlas 上传调用链占 64.92%，Adreno 复制路径的 GPU 内存分配占 29.74%。beta.9 主线程共 893 样本，上传调用链占 39.55%；上述分配不再出现在 0.5% 阈值报告中。剖析进程会影响性能，未用其 FPS 替代上表的无剖析对照。

beta.9 使用 RGBA 纹理存储及 GPU 视图的 R/B 通道映射，保留原始 BGRA 像素，不增加 CPU 换色。仅在 Android 且设备支持 TEXTURE_COMPONENT_SWIZZLE 时启用；不支持时沿原格式路径处理。小图、文字和连续替换同样遵循视图映射；GPUI 像素回归通过。非 Android 产品纹理选择不变。

## 已实机验证：两槽位帧缓存仍未达到稳定 120 FPS

后续 Android 候选保留最多两个已解码帧，吸收两次 UI 刷新之间的集中输出。UI 取帧时，超过两个请求刷新间隔的旧帧在有新帧可用时跳过；静止桌面的最终帧继续保留。关闭、切屏及离线清理都排空两个槽位。非 Android 继续使用单槽位策略。计数仍在 UI 接受实际帧时增加，不在入队时增加。

生产帧选择代码独立于编解码器和窗口库。直接引用该源文件、使用 Android 包锁定的 crossbeam-queue 0.3.14 / crossbeam-utils 0.8.23，运行两项回归：相邻突发帧跨显示时钟消费；过载跳过旧帧、保留静止末帧及完整清空。两项均通过。完整 RustDesk 根库测试未在本机运行，这些核心算法回归不替代真机验收。

初始 beta.10（40010）源码 `a92cfe75a920094f069b8b7bd54544d1afeae507`，Android [构建 43862413452](https://github.com/isarmg/xscc/actions/runs/43862413452) 的 smoke、management 均成功。管理 APK SHA-256 为 `265f78828e22d4c4ac15d4354d708e33bf75ea1cb12fb0cab4e8e355fc083a77`；本地校验来源、包版本和原签名身份通过。

用户在安装前切换无线调试，首次安装因 USB 断开而未执行。用户随后重新接入 USB，管理 APK 已成功覆盖安装，设备读取确认版本为 4.0.0-beta.10 / 40010，原绑定保留。

beta.10 完成两轮各 45 秒的原生源测试，均自行退出。无剖析稳态窗口的 UI 提交范围 78–97 FPS、中位数 94；独立剖析轮接收/解码中位数 118、UI 中位数 96（不能用剖析轮取代上表对照）。无剖析轮排队 p95 的中位数约 16.9ms，比 beta.9 增加约 7.4ms，是多保留一帧的实际延迟代价。该变化改善了提交比例，没有达到稳定 120 FPS。

窗口回调平均耗时在两轮中约为 9–10ms，已超过 120FPS 的 8.33ms 预算，剩余问题位于界面帧处理/提交链路。新剖析中没有重新出现之前的显著 GPU 图像分配热点，不能再把全部问题归为虚拟显示器固定 60Hz。具体 GPU 等待与 CPU 绘制耗时仍需进一步分段测量，未据此猜测某个单独驱动调用已是唯一瓶颈。

测试结束已断开会话，临时 USB 常亮配置已恢复原值 0。虚拟屏继续保留 1920×1080、120Hz，物理主屏仍为 1920×1080、60Hz。未创建/撤销虚拟屏，未操作浏览器或桌面全屏，无测试源进程遗留。

核心算法后续抽为独立生产模块，语义未变；[整合源码 b22319fea 的 Android 构建](https://github.com/isarmg/xscc/actions/runs/43866974023)、iOS 构建与 GPUI 框架验证均通过。手机安装包仍明确记录上述 a92cfe75a920 源码，未将源码整合后的自动候选覆盖到手机。

## 已测：合并 Android 上传和绘制提交

USB 连续测试继续。将 Android 大图最新快照的映射上传记录进主绘制 encoder，随绘制一次提交，取消原来每帧单独的上传提交。新增按秒汇总的 acquire / upload / render / finish / submit / present 墙钟耗时；render 包含其中的上传与提交，不应把这些列相加。尚未据此声称达到 120 FPS。

回归范围：`android_image_upload.rs`、`wgpu_atlas.rs` 的 Android 大图上传及 `wgpu_renderer.rs` 的 Android 编码/提交入口；其他平台产品沿原 atlas 上传路径。纯布局算法移入 `image_upload_layout.rs`，保持无 GPU 的独立测试；原像素回归使用 641×480 大图以覆盖映射上传、行对齐、连续替换及删除后不绘制。GPU 回收仍由提交完成后的回调控制。

Android [构建 43873483437](https://github.com/isarmg/xscc/actions/runs/43873483437) 的 smoke、management 均成功。管理 APK 源码 b28a86835b481f50d5c1b857213a76f487f13b87，版本名称 4.0.0-beta.11，实际 versionCode 仍是打包脚本固定的 40010，不误记为 40011。已校验产物外层摘要、APK 内层摘要、来源及原签名身份，通过 USB 成功覆盖安装，绑定保留。

两轮均运行同一原生窗口测试源 45 秒，随后 3 秒静止尾帧并自动退出；稳态仍取开始后第 10–40 秒。

相比 beta.10 的 UI 中位数 94、回调 9.29ms，界面现在基本跟上接收/解码，回调低于 120FPS 的 8.33ms 预算。第一轮 Android GPU 分段平均耗时的窗口中位数：取显示缓冲 0.082ms，上传 0.752ms，render 2.093ms，encoder finish 0.558ms，queue submit 0.481ms，present 0.562ms。render 包含上传、finish 和 submit，不把各列相加。

复测第 25 秒只读采集本应用 SurfaceFlinger 时间戳。126 个有效已呈现缓冲覆盖 1.065 秒，实际呈现频率约 117.33Hz；间隔中位数 8.258ms、p95 8.259ms，3 个间隔超过 12ms。此为短窗口系统呈现证据，不扩写为整场面板扫描或长时稳定 120FPS。

复测有一次接收/解码/UI 同时降至 78 / 76 / 77FPS，UI mailbox dropped 为 0。对应主机日志仍输出约 116–119FPS；剩余波动位于主机输出到客户端接收/解码之间，当前证据不能区分传输与接收调度，也没有证明 UDP 丢包。未据此猜测原因后调整拥塞控制、降低画质或修改驱动。

最终回归面：现有 android_image_upload.rs 的提交改为记录到传入 encoder；wgpu_atlas.rs 的 Android 大图替换与刷入改为保留最新快照、在绘制前编码；wgpu_renderer.rs 的 Android 绘制入口接入复制和按秒耗时汇总。gpui_wgpu.rs 只注册模块；.github/workflows/gpui-android-smoke.yml 只把无 GPU 布局测试路径改到抽出的文件。其他平台产品 atlas 路径保留，未改协议、Windows 安装、驱动或显示器布局。现有 8 项 atlas 回归、2 项纯布局回归均通过；渲染像素回归实际覆盖大图映射、非对齐行宽、多次替换及删除。模块声明后续仅按 rustfmt 排序，运行语义不变。
