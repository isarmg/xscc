# 局域网临时直连

仅用于当前测试阶段。控制端输入 IP 即可连接，不经过管理服务器，也不需要被控端逐次确认。

## 测试包

测试包启用 `test-lan-direct` feature，带有 `TEST-ONLY.txt` 和能力清单。普通构建默认不包含它；打包时会核对二进制的实际能力，拒绝将测试能力混入普通包。

正常启动和 21118 端口仍使用服务器授权。测试监听需要单独启动，默认端口为 21119。

## 启动被控端

在已登录的桌面中运行测试版 Host，把示例 IP 换成本机的私网 IPv4 地址。

Windows PowerShell：

```powershell
$env:XSCC_TEST_LAN_BIND = '192.168.1.20:21119'
& '.\xscc-host.exe' --test-lan-host
```

Windows 使用当前进程权限，不经过已安装的 SYSTEM 服务。普通 Host 界面不会因为设置了该变量而打开测试监听。测试命令会打开独立控制台窗口显示监听地址和风险提示；关闭该窗口即可结束测试进程和监听。

Linux Wayland：

```sh
XSCC_TEST_LAN_BIND=192.168.1.20:21119 ./xscc-host --test-lan-host
```

Linux 测试构建不支持 `drm`，使用桌面 portal 的屏幕共享与输入权限。此独立模式关闭音频，以免占用已安装服务的共享音频 IPC；正常管理模式不受影响。

macOS：

```sh
XSCC_TEST_LAN_BIND=192.168.1.20:21119 '/Applications/XSCC Host.app/Contents/MacOS/xscc-host' --test-lan-host
```

macOS 仍需系统的屏幕录制与辅助功能权限。结束前台进程即可关闭测试监听，不要将它注册为开机服务。

## 连接与访问范围

在控制端“局域网直连（测试）”中输入 `192.168.1.20` 或 `192.168.1.20:21119`。两端必须位于本地接口直连的私网 IPv4 子网；不支持域名、公网地址、回环、IPv6 或中继。程序不自动修改防火墙。

此模式没有身份认证，同一允许子网内可达的设备都能控制桌面。传输仍加密，但不能防止主动中间人冒充。请只在隔离测试网络中使用；VPN 和虚拟网卡也可能满足子网条件。

## Android / iOS / iPadOS 控制端

移动 GPUI 测试构建显式启用 `experiments/gpui-mobile-management` 的 `test-lan-direct` feature（同时启用 `mobile-session`）；默认管理构建不包含 IP 输入框或测试握手入口。移动端仍然仅作为控制端，不能启动被控监听。

无需绑定管理服务器，在标明 TEST ONLY 的“局域网直连（测试）”区域输入上述桌面测试监听的私网 IPv4 即可连接。需要允许系统的本地网络访问。输入的地址仅保留在当前界面内，不保存为管理设备或授权身份。

直连沿用现有移动会话的画面、触控、软键盘、音频开关、屏幕选择及帧率控制；也可切换为仅查看。功能仍受被控平台能力及系统权限限制，Linux 前台测试监听仍禁用音频。进入后台或断开时关闭会话并释放输入和音频，返回前台不会自动重连。正常授权设备列表仍走管理服务器授权。

## 结束测试

正式发布前删除 `test-lan-direct` feature、测试界面、前台命令及后端入口，并将 beta workflow 默认模式恢复为 `managed`。不能把测试包直接改名为正式包。
