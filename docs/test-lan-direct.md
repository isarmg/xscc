# 临时 IP 直连

仅用于当前测试阶段。控制端输入 IP 即可连接，不经过管理服务器，也不需要被控端逐次确认。

## 测试包

测试包启用 `test-lan-direct` feature，带有 `TEST-ONLY.txt` 和能力清单。普通构建默认不包含它；打包时会核对二进制的实际能力，拒绝将测试能力混入普通包。

正常启动和 21118 端口仍使用服务器授权。测试监听需要单独启动，默认端口为 21119。

## 启动被控端

在已登录的桌面中运行测试版 Host，把示例 IP 换成本机要监听的 IPv4 或 IPv6 地址。也可使用 `0.0.0.0:21119` 或 `[::]:21119` 监听对应地址族的所有接口；控制端应填写实际可达的主机 IP，而非通配监听地址。

Windows 测试版优先使用界面：

1. 双击 `xscc-host.exe`，找到“IP 直连 · 仅测试”。无需绑定管理服务器；即使普通服务尚未安装，测试入口仍可用。
2. 监听地址留空使用 `0.0.0.0:21119`，或填写合法 IPv4 / IPv6 监听地址。阅读无身份验证的风险提示，点击“开启 IP 直连（测试）”。
3. 等待界面显示“测试监听已开启”及实际端口。手机填写界面列出的可达地址；默认 21119 端口时可只输入 IP。`0.0.0.0` 和 `::` 是监听通配地址，不能作为手机连接目标。
4. 点击“停止 IP 直连”或退出 Host 窗口关闭测试监听。此开关不持久化，下次打开默认关闭。启动失败会显示具体错误，不会自动修改防火墙。

界面管理独立测试子进程，并通过 Windows Job 在界面进程退出时清理它。普通管理服务和测试监听分别显示状态；管理服务初始化错误不代表测试监听已开启或失败。

需要终端启动时，也可使用 PowerShell：

```powershell
$env:XSCC_TEST_LAN_BIND = '192.168.1.20:21119'
& '.\xscc-host.exe' --test-lan-host
```

Windows 使用当前进程权限，不经过已安装的 SYSTEM 服务。普通 Host 界面不会因为设置了该变量而打开测试监听。手动测试命令会打开独立控制台窗口显示监听地址和风险提示；关闭该窗口即可结束测试进程和监听。界面启动则在 Host 窗口中显示状态。

Linux Wayland：

```sh
XSCC_TEST_LAN_BIND=192.168.1.20:21119 ./xscc-host --test-lan-host
```

Linux 测试构建不支持 `drm`，使用桌面 portal 的屏幕共享与输入权限。此独立模式关闭音频，以免占用已安装服务的共享音频 IPC；正常管理模式不受影响。

macOS：

```sh
XSCC_TEST_LAN_BIND=192.168.1.20:21119 '/Applications/XSCC Host.app/Contents/MacOS/xscc-host' --test-lan-host
```

macOS 仍需系统的屏幕录制与辅助功能权限。结束前台进程即可关闭测试监听，不要将它注册为开机服务。

## 连接与访问范围

在控制端“IP 直连（测试）”中输入 IPv4 或 IPv6 地址，例如 `192.168.1.20`、`192.168.1.20:21119`、`2001:db8::20` 或 `[2001:db8::20]:21119`（文档示例地址须替换）。不指定端口时使用 21119；IPv6 指定端口时须加方括号。测试入口不检查私网、公网、回环、接口或同子网条件；仅解析 IP 和端口格式，不解析域名，不使用中继。程序不自动修改防火墙或路由。

此模式没有身份认证，任何能到达测试监听端口的设备都能直接控制桌面，不需要绑定或被控端确认。暴露到公网会让互联网中的其他设备获得同样的控制能力。传输仍加密，但不能防止主动中间人冒充。

## Android / iOS / iPadOS 控制端

移动 GPUI 测试构建显式启用 `experiments/gpui-mobile-management` 的 `test-lan-direct` feature（同时启用 `mobile-session`）；默认管理构建不包含 IP 输入框或测试握手入口。移动端仍然仅作为控制端，不能启动被控监听。

无需绑定管理服务器，在标明 TEST ONLY 的“IP 直连（测试）”区域输入上述桌面测试监听的 IPv4 或 IPv6 地址即可发起连接。访问本地网络时仍须允许操作系统的本地网络权限。输入的地址不会保存为管理设备或授权身份。

直连沿用现有移动会话的画面、触控、软键盘、音频开关、屏幕选择及帧率控制；也可切换为仅查看。功能仍受被控平台能力及系统权限限制，Linux 前台测试监听仍禁用音频。进入后台或断开时关闭会话并释放输入和音频，返回前台不会自动重连。正常授权设备列表仍走管理服务器授权。

## 连接失败时检查

测试入口必须连接独立启动的测试 Host 监听，不能连接普通管理端口 21118。检查 Host 控制台显示的实际监听地址与端口、目标主机是否能从控制端网络到达，以及系统网络权限、防火墙和 NAT/端口映射。移除应用的地址范围限制并不会自动让不可达的网络连通；需要结合具体错误和主机日志定位，不能据此断定失败原因。

## 结束测试

正式发布前删除 `test-lan-direct` feature、测试界面、前台命令及后端入口，并将 beta workflow 默认模式恢复为 `managed`。不能把测试包直接改名为正式包。
