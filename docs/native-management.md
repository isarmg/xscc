# 原生管理接入

## 使用

1. 在 xscs 网页创建控制端、被控端实例，并设置两者之间的允许控制关系。从任意一侧编辑的是同一份关系。
2. 在各自 xscc 首页的“XSCC 实例管理”中输入 HTTPS 服务端地址和对应实例授权码。
3. 被控端可填写最多四个 IP/域名和端口，每行一个，默认端口 21118。留空时从默认网络接口采集本机地址，使用当前实际监听端口。跨网络连接可填写可达域名及映射端口；不会自动配置端口映射。
4. 控制端从“允许连接的被控端”列表发起连接。被控端显示允许接入的控制端。管理授权通过后，继续使用原生密码或本地确认。
5. 撤销授权、解绑或管理连接失效后，既有受管会话关闭。解绑先让服务端作废当前凭据，再清除本地绑定；服务端不可达时保留身份，稍后重试。

画质、帧率、编码和硬件选择仍在控制端的原生会话界面中完成。服务端仅管理实例、关系和诊断，没有这些设置的写入任务。

## 生命周期和存储

`managed` 默认启用，控制端支持 Linux amd64、macOS 26 Apple Silicon、Windows 11 amd64、iOS 26 arm64 和 Android arm64（API 29 起）；被控端仅支持前三个平台。`src/management` 是原生进程适配层，`crates/native-management` 持有管理生命周期。桌面使用已有 `--server` 进程和 Tokio runtime；控制端即便关闭本机监听也会启动管理任务。正常 IPC 关闭先等待管理任务退出。进程被强制终止时，依靠持久执行事实恢复。

桌面 GUI 经现有主 IPC 请求绑定、状态、地址修改和会话证明。请求发送前验证内核提供的对端身份与当前程序文件；后台也验证调用方。仅允许相同用户，不扩大 `_service` 通道的允许操作。GUI 只收到脱敏状态、可见对端和短期连接证明，不接收管理凭据或配对密钥。

Unix 存储位于系统账户数据库所给主目录的 `xscc-managed`，忽略 `HOME`；目录 0700、文件 0600，拒绝符号链接、不安全权限和多硬链接文件。Windows 使用系统 LocalAppData 下的 `xscc-managed`，私有 DACL 仅允许当前账户、SYSTEM 和管理员。使用独占锁、原子发布与文件同步；目录或凭据损坏时拒绝连接，不生成替代身份绕过错误。

移动端从系统 Application Support 目录创建私有管理目录，不使用外部存储或可共享的 Documents。应用初始化显式启动一个进程级管理循环；所有远程会话共用，GUI 通过原生桥接调度请求，不启用桌面 IPC 或被控监听。移动端 HTTPS/WSS 使用内置公共 CA 信任根，继续强制验证服务端证书。

安装 UUID 在首次启动持久保存，解绑不会改变。发起注册前保存待注册的身份、随机凭据和目标服务端；响应丢失后查询已有身份。执行回执按服务端/实例/安装隔离；已确认摘要保留为去重记录。未确认结果最多 4096，保留记录最多 131072；容量耗尽时报告错误，不删除去重事实。

## 会话身份与撤销

服务端在 HTTPS/WSS 授权策略中给双方后台所有者提供同一份配对密钥，派生上下文包含完整双方安装绑定及双方凭据摘要。其他对端、重新安装或凭据轮换得到不同密钥。该密钥不进入 GUI、日志或执行记录；策略的 `Debug` 输出隐藏它。

原生加密握手之后、登录之前交换有界的管理证明。双向 HMAC-SHA256 包含 manager/device/installation 绑定、密钥代际、双方随机数和本次加密握手实际验证的主机签名公钥。主机与控制端使用不同证明域，避免反射、重放和在不同主机通道间转发证明。主机不信任来源 IP 或客户端自报的公钥。

每次证明与会话检查都重新读取有效授权。服务端每五秒刷新关系，租约有效期三十秒；WSS 断开立即清空观察。原生两侧利用已有一秒状态定时器检查，控制端 IPC 检查超时也会关闭。首次绑定时，之前的非受管会话也会关闭。未绑定或编译时关闭 `managed` 保留原有直接加密和身份确认流程。

本轮不改变音视频传输、捕获、编解码和输入实现。完整应用构建与物理主机串流验收见 [验收条件](readiness.md)。移动端提供控制端绑定、授权列表和相同的会话证明；客户端注册前检查实例角色，服务端 Hello 也拒绝移动端被控角色。iOS/Android 仅在应用前台使用，不提供被控功能。

## 既有路径的必要变更

- `src/server.rs`：在现有后台启动中启用管理所有者；在加密握手后、原生登录前校验实例证明。
- `src/server/connection.rs`：保留连接许可，用现有定时器关闭失效会话，并识别已验证实例的登录目标。密码、本地确认和输入权限仍由原生流程检查。
- `src/client/io_loop.rs`：受管连接走授权列表及双向证明，随后复用原来的会话循环；在现有状态定时器检查授权。未配置及关闭功能时保留原连接路径。
- `src/ipc.rs`、`src/ipc/auth.rs`：在现有主 IPC 中加入经过用户和程序身份验证的管理请求；正常关闭时停止管理任务。
- `src/flutter_ffi.rs`、桌面首页与移动连接页：增加脱敏管理入口和共用主机列表，移动初始化使用系统私有目录。只修改桥接输入，生成文件继续由 CI 产生。
- `src/ui_interface.rs`：将桥接请求投递到桌面已有状态循环；FRB 1.x 普通导出在工作线程运行，不能直接导出 Rust async fn。移动端在应用初始化边界显式持有一个管理 runtime。
- `Cargo.toml`、协议固定 revision 和管理 CI：加入本地原生管理库，桌面三平台单独运行测试，并交叉检查 iOS arm64、Android arm64；应用 CI 在本分支运行完整构建检查。

注册和绑定存储从应用预备模块移入原生管理库，供真实生命周期调用，并加入 Windows 平台实现；来源应用仓库保持不变。
