2026-10-28 审查建议核实与实现

范围
用户提供 XSCC 与 XSCS 两份第三方审查会话。按当前源码核实建议，不把其中的示例、平台收缩和时间估算视为用户指令。XSCS 的独立改动已在其仓库 main bad4d1d 提交；本文件记录 XSCC。

已实现
1. 根 Rust 核心、桌面、移动产品及已内嵌 hwcodec 统一工作区/锁文件。以 beta.12 桌面锁为解析基线，逐项核对保留桌面 1146 个、移动 1138 个旧包的名称、版本、来源和 checksum；合并后 1199 个包。新增的是原根工作区及移动测试的既有依赖，不将锁文件中可选历史包误当成 Android 生产依赖。
2. 保留现有 iOS libc=0.2.189。根 resolver=3 与之前 edition2024 产品一致。移除原来只作用于旧根构建、未被独立产品使用的 release profile；继续使用此前正式产品的 Cargo release 默认值，开发 debug=0。Windows build-info 和 Android 产物都保存根锁文件来源。
3. FFmpeg RAM 同步 callback 复用上一包已归还的 NV12/YUV420 plane Vec，公开借用和 C ABI 不变，不跨帧复用 GPU 裸句柄。同尺寸、格式和步长稳态原四次堆分配降为零；布局变化会释放旧帧缓冲，CPU plane 数据仍复制。参考帧完整解码，只对同次 decode 返回的最后一张可转换图像做 RGB 转换。
4. use_i444 读取能力表时借用，删除整表 clone。删除零调用的 NativeManager::policy，避免复制包含会话密钥的全部策略。当前状态、授权租约和撤权检查不变。
5. gpui-host 增加一秒窗口数字观测：采集耗时及 Ready/Empty/WouldBlock/Failed 数量、转换耗时、Fresh/Replay/Repeat 编码分发平均/最大耗时和目标周期。encode_calls 是尝试次数，不能当作成功码流 FPS；不新增线程、锁、依赖或身份/凭据字段。capture_gdi 在 Windows 记录捕获器现有 is_gdi 观察，其余平台为2（未知）；portable 捕获代理的该观察不能证明后台真实捕获方式。
6. Windows/Unix 桌面候选流程也由 PR 触发。原生 hwcodec 单元测试的既有 Windows 开发助手链接 SDL，运行时路径仅在该 CI 测试进程内补齐，不进入产品。Linux host 增加 DRM/drm-wake 编译；真实原生库构建后运行三项解码缓冲回归，拒绝空过滤。来源检查验证 hwcodec 459 个原始导入文件，排除 upstream.json 已明确登记的本地补丁；不篡改原始 hash 清单。新增三项来源检查合同回归。 首轮统一工作区 CI 中，Clippy 将新纳入工作区的既有依赖一并按产品 -D warnings 检查，暴露 hbb_common 旧 lint；产品命令显式 --no-deps 恢复原独立产品的 lint 边界，保留产品自身 -D warnings 与管理库独立严格检查。依赖照常编译与测试。Framework 与 iOS CI 显式保留原输出目录，根锁变化也触发 framework 验证。

未照搬的结论
- Rust 1.99 的 Windows 非零 thread::sleep 已用高精度 waitable timer；官方实现 library/std/src/sys/thread/windows.rs108-135。没有新增全局 timeBeginPeriod 或第二套计时器。
- 当前 streaming 路径没有等待旧三秒 ACK 屏障；Windows GPUI 也没有绘制后再固定睡一个刷新周期的证据。
- drm_capturer.rs 报告的3358行 Xcursor 乘法位于 cfg(test) 的 ignored 本地主题调查，不是生产捕获入口。没有将它冒报为生产越界漏洞。
- 当前正常 VideoHandler 输出 ARGB，ABGR 标量交换不在这条实际路径；没有改无关分支。
- Linux 的直接 NV12 转换微基准优于两段转换，但不足以覆盖旧 Windows 注释中的实测依据，本版保留 Windows 路径。
- 不删除跨时间授权复核、密码/持久化边界、安全源校验、慢会话资源边界；不按未验证的理论估算重写采集线程/GPU 纹理生命周期。
- GPUI vendor 独立开发工作区、历史可选源码、全仓品牌/安装目录迁移和进一步拆 crate 不包含在本批改动。

测量边界
安装中的 beta.12 已确认实际采用 HEVC/D3D11VA；旧 beta.11 的软件-only 探测不能代表本轮。精确对齐 45 秒诊断：CPU 生成119.88 FPS、诊断 GPUI 提交57.30 FPS，稳定窗口21项一秒样本中真实会话接收中位28/解码29/提交28 FPS，decode p95 的一秒样本中位23.25ms。该数字是优化前基准，不能标成 beta.13 提升，也不是物理显示 scanout。第一次30秒诊断的尾部49-50样本位于诊断结束后，已纠正。
50帧缓冲局部微基准减少200次分配到0，但1080p和4K中位仅分别节省约0.05ms，不能宣称解决约15ms整段解码处理。Android 用户尚未安装 beta.12，实体手机帧率无新结论。
