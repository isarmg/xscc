# XSCC GPUI 0.1.0-beta.21

同步最新 main 的原生会话修复，并整理桌面与移动端界面、刷新率和虚拟显示器控制。本次 Windows、Linux、macOS、Android 和 iOS 的发布包要求来自同一提交，保留原生构建、签名策略及校验清单。

## 更新

- Windows 显示设备变更前等待捕获器与编码器实际释放，结束后恢复取屏；退出会话、配置途中断开和移除失败使用同一安全清理顺序，超时保留设备并报告错误。已保存的零数量不会被自动无头登录覆盖。
- 已加载的虚拟屏数量与模式目录未变时，直接修改当前显示模式，避免不必要的驱动重启。驱动及实际支持范围仍按系统结果确认。
- 刷新率菜单使用被控屏真实支持的 Hz，分辨率独立设置，显示器选择改为下拉。只改变 Hz 也会通知客户端更新实际模式；画面目标随确认的 Hz 调整，不同屏幕分别按自己的观看端计算 FPS 和码率上限。
- 移动端鼠标模式显示清晰的本地指针，箭头尖端复用实际点击坐标；全屏画面之外为纯黑。Android 会话请求同物理尺寸下系统支持的最高刷新率，退出恢复原窗口偏好。
- 当前屏离线时清除旧帧并释放输入；UI 发送失败后退出原连接，保留原有有界视频队列与关键帧恢复。同步最新 Enigo 错误格式化修复。
- 独立 One-KVM 裸机宿主源码及五轮审计记录已并入，遵循其独立构建和验证流程。

## 安装与验证范围

Android 使用原有预览签名和包名，版本为 0.1.0-beta.21 / code 21，可覆盖安装并保留绑定。Windows/macOS 应用为未签名预览；iOS IPA 的实际短版本为 0.1.0，需要自行签名。

所有发布候选都必须完成对应源码的原生构建。包内构建信息、发布来源清单及 SHA256SUMS 可用于核对；手动触发的原生构建与 push 构建使用相同的源码、管理模式和摘要检查。

回归、类型检查和原生编译不能代替实机高帧率或内核稳定性验收。本轮未使用 Android USB 调试，未声称已达到稳定 120 FPS；实际帧率仍受采集、编码、网络、解码、系统显示策略及共享同一视频流的观看端影响。取屏资源未安全释放时，不强行停用显示设备。
